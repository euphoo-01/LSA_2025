# Правила разработки и архитектурные концепции компилятора LSA-2025

## 1. Архитектурные принципы
- **Лексический анализ:** Реализован с использованием **Конечных Автоматов (Finite State Automata - FST)**. Лексер преобразует исходный текст в поток лексем.
- **Синтаксический анализ:** Реализован с использованием **Автоматов с магазинной памятью (Pushdown Automata)**. Используется алгоритм **MFST** (Multi-chain Finite State Transducer) на основе грамматики в нормальной форме Грейбах.
- **Обработка выражений:** Для вычисления и генерации кода выражений используется **Обратная Польская Запись (Reverse Polish Notation - RPN)** (ПОЛИЗ).
- **Генерация кода:** Генератор создает код на языке **Assembler (NASM)** для архитектуры x86-64 (на основе имеющихся шаблонов в `NasmGen`).

## 2. Спецификация языка LSA-2025

### Типы данных
1. **unsigned integer**: Беззнаковый целочисленный тип.
2. **char**: Символьный тип (базируется на кодировке Windows-1251).
3. **logic**: Логический тип (принимает значения 1 или 0).

### Сравнение переменных
1. unsigned integer можно сравнить только с unsigned integer и logic (проверка на истинность)
2. logic можно сравнить только с logic
3. char можно сравнить только с char и logic (проверка на истинность)

### Основные конструкции
- **Точка входа:** Ключевое слово `main`. Обязательна, единственна, должна возвращать значение.
- **Функции:** Объявляются через ключевое слово `func`.
  - Синтаксис: `func <тип> <имя>(<параметры>) { ... }`.
  - Возврат значения: оператор `send`.
  - Область видимости: Глобальная (объявляются до `main`).
- **Условный оператор:**
  - `if (<условие>) { ... }`
  - `differ { ... }` — аналог `else`.
- **Цикл:**
  - `because (<инициализация>; <условие>; <шаг>) { ... }` — аналог цикла `for`.

### Стандартная библиотека функций
- **Ввод/Вывод:**
  - `readch()` — чтение символа.
  - `writech(ch)` — вывод символа (в текущей реализации расширен для вывода чисел).
- **Математика:**
  - `sqrt(x)` — квадратный корень.
  - `pow(x, y)` — возведение в степень.
  - `getMin(x, y)` — минимум.
  - `getMax(x, y)` — максимум.
  - `isPrime(x)` — проверка на простое число.
- **Работа с символами:**
  - `toUpper(ch)` — перевод в верхний регистр.
- **Архитектурное устройство:**
  - Отдельный cmake проект, либо папка, где настроено, что он компилируется в статическую библиотеку.
  - Написан на C++
  - Путь до скомпилированной библиотеки захардкожен в NasmGen.cpp
  - Библиотека подставляется в выходной NASM код в процессе компиляции
  - Ни в коем случае реализация не должна находиться в NasmGen.cpp

### Операторы
- **Арифметические:** `+`, `-`, `*`, `:`, `%` (остаток).
- **Сравнения:** `==`, `!=`, `<`, `>`, `<=`, `>=`.
- **Битовые/Логические:** `~` (инверсия).
- **Унарные:** `++`, `--`.
- **Присваивание:** `=`.
*Важно!* Арифметические операции можно совершать с unsigned integer и char. Тогда char переводится в соответствующий ему код в таблице кодировки Windows-1251
Если значение unsigned integer присваивается char, то его значение переводится в символ согласно windows-1251

### Обязательные семантические проверки
1. Деление на 0
2. Наличие точки входа в программу (main)
3. Наличие возврата у функции (в этом языке нет void)
4. Отлавливать бесконечные циклы
5. Отлавливать бесконечные рекурсии (сделать так, чтобы поведение было предсказуемым)
6. Необходимо предусмотреть все варианты, когда компилятор может выдать ошибку. Нужно чтобы любая ошибка имела предсказуемое поведение (была отловлена и отображена в консоли).

## 3. Важные правила редактирования
1. **Структура проекта:** Не нарушать модульную структуру (`Lex`, `Syn`, `Sem`, `Gen`).
2. **Коды ошибок:** При добавлении проверок использовать диапазоны кодов из спецификации:
   - **0-99:** Системные ошибки.
   - **100-115:** Ошибки параметров и ввода-вывода (открытие файлов, создание логов).
   - **700-750:** Лексические ошибки.
   - **300-350:** Семантические ошибки.
   - **600-610:** Синтаксические ошибки.
3. **Соглашения:**
   - Кодировка исходных файлов: Windows-1251.
   - Все функции должны быть объявлены до их использования (в коде LSA).

## 4. Стиль написания кода
1. Основные блоки кода должны быть обозначены комментарием на русском языке, с маленькой буквы.
2. Комментарии должны быть краткими и лаконичными
3. Комментариев должно быть немного
4. Обязательные комментарии в сложных местах для объяснения причины выбора именно такого решения. Должно быть очень кратко
5. Комментарии должны быть написаны понятными для людей, со стилистикой человека
6. Код должен быть написан профессионально
7. Код должен предусматривать ошибки
8. Код должен быть простым и понятным
9. Код должен быть написан в старом стиле
10. Код должен быть совместим с Archlinux и процессором AMD x64.
